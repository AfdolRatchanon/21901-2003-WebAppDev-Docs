แผนการสอนแบบฐานสมรรถนะ (Competency-based Teaching Plan)
สัปดาห์ที่ (Week)     15

รหัสวิชา (Code)     21901-2003  	วิชา (Subject)     การพัฒนาเว็บแอปพลิเคชัน                                                        
หน่วยที่ (Unit)       8		ชื่อหน่วย (Name of Unit)     Test & Deploy (การทดสอบและการนำระบบขึ้นใช้งานจริง)
หัวเรื่อง (Sub Unit)/งาน (JOB) การเขียนแผนการทดสอบ (Test Plan)

1.  สาระสำคัญ (Concept) 
	ก่อนที่แอปพลิเคชันจะถูกนำไปใช้งานจริง (Go Live) กระบวนการที่สำคัญที่สุดคือการทดสอบ (Testing) เพื่อให้มั่นใจว่าซอฟต์แวร์ไม่มีข้อบกพร่อง (Bugs) หรือพฤติกรรมที่ไม่คาดคิด การเขียนแผนการทดสอบ (Test Plan) และกรณีทดสอบ (Test Cases) อย่างเป็นระบบ จะช่วยให้นักพัฒนาสามารถตรวจสอบการทำงานของแต่ละหน้าจอ ฟังก์ชันการทำงาน รวมถึงการรับส่งข้อมูล (API) ได้อย่างครอบคลุมตั้งแต่ต้นจนจบ (End-to-End) ลดปัญหาที่จะเกิดขึ้นกับผู้ใช้งานจริง

2.  สมรรถนะหลัก/ย่อย (Unit of Competence / Element of Competence)
1. มีความเข้าใจหลักการและประเภทของการทดสอบซอฟต์แวร์ (Software Testing)
2. มีทักษะในการเขียนเอกสารแผนการทดสอบ (Test Plan) ที่ครอบคลุมขอบเขตการทำงานของโปรเจกต์
3. มีความสามารถในการออกแบบและเขียน Test Cases สำหรับทดสอบฟังก์ชันต่างๆ
4. มีความตระหนักในคุณภาพของซอฟต์แวร์ (Quality Assurance) และความรับผิดชอบ

3.  จุดประสงค์เชิงพฤติกรรม (Behavioral Objective)
1. อธิบายความสำคัญของการทำ Test Plan ก่อนนำระบบขึ้นใช้งานจริงได้
2. ออกแบบและเขียน Test Cases เพื่อครอบคลุมเงื่อนไขการทำงานในแต่ละโมดูลได้อย่างถูกต้อง
3. ดำเนินการทดสอบระบบของตนเอง (Manual Testing) ตามแผนการทดสอบที่เขียนขึ้นได้
4. บันทึกผลการทดสอบและระบุข้อผิดพลาด (Bugs) ที่พบได้อย่างชัดเจน
5. เตรียมเครื่องคอมพิวเตอร์และสภาพแวดล้อมเพื่อการเรียนได้
6. เปิดโปรแกรมหรือเอกสารเพื่อศึกษาเนื้อหาควบคู่ได้อย่างถูกต้อง
7. สรุปเนื้อหาได้
8. แสดงความสนใจต่องานที่ได้รับมอบหมายได้เป็นอย่างดีเมื่อครูมอบหมายงานให้ทำ
9. ประยุกต์แนวทางการพัฒนาแบบเศรษฐกิจพอเพียงในเรื่องการประหยัดอดออมในการใช้อุปกรณ์อย่างรู้คุณค่า
10. ประยุกต์ใช้เป็นแนวทางในการดำเนินชีวิตอย่างสุจริตได้
5.  กิจกรรมการเรียนรู้ (Teaching / Learning Activities)
	-  ทบทวนระบบทั้งหมดที่สร้างขึ้นมาตั้งแต่วันแรกถึงปัจจุบัน
	เรื่องที่/งานที่ (Sub Topic/Job)  :   การจัดการคุณภาพซอฟต์แวร์
	หัวข้อที่/งานที่ (Sub  Unit/Main Job)  :  การเขียนแผนการทดสอบ (Test Plan)
	ขั้นนำเข้าสู่บทเรียน  (Motivation)  
1. ครูเล่ากรณีศึกษาของซอฟต์แวร์ที่มีบั๊ก (Bug) ร้ายแรงหลุดไปถึงมือผู้ใช้จริงจนเกิดความเสียหาย (เช่น ข้อมูลหาย, คิดเงินผิด)
2. ครูถามนักเรียนว่า "เราจะรู้ได้อย่างไรว่าระบบเบิก-จ่ายอุปกรณ์ที่สร้างมาทำงานได้ 100% โดยไม่มีข้อผิดพลาด?"
3. ครูอธิบายความสำคัญของการทำ Quality Assurance (QA) ผ่านการเขียน Test Plan ก่อนส่งมอบงาน
	ขั้นการให้เนื้อหาความรู้  (Information)  
1. ขอบข่ายเนื้อหาหลัก
Test Plan: องค์ประกอบของแผนการทดสอบ (ขอบเขต, ระยะเวลา, ผู้ทดสอบ, เกณฑ์การผ่าน)
Test Cases: การเขียนกรณีทดสอบที่ประกอบด้วย ขั้นตอนการเตรียม (Pre-conditions), ขั้นตอนปฏิบัติ (Steps), ผลลัพธ์ที่คาดหวัง (Expected Results), และผลลัพธ์จริง (Actual Results)
Types of Testing: อธิบายความแตกต่างของ Unit Test, Integration Test และ End-to-End (E2E) Test (เน้นทำ Manual E2E สำหรับคอร์สนี้)
2. แนวทางการจัดกิจกรรมการสอน
2.1 จัดเตรียมเนื้อหาให้นักศึกษา (`wk8-content1-testplan.md`)
2.2 ถามและตอบคำถามนักเรียนพร้อมกับอธิบายตัวอย่างการเขียน Test Case ที่ดี (เช่น กรณีผู้ใช้พิมพ์อีเมลผิดรูปแบบ)
2.3 สาธิตการเขียน Test Case 1 กรณี และทดลองทำตามขั้นตอนในโปรเจกต์
ขั้นการประยุกต์เนื้อหา  (Application) 
1. ให้ นศ. ศึกษาเนื้อหาและออกแบบ Test Plan เบื้องต้นสำหรับระบบเบิก-จ่ายอุปกรณ์
2. ให้ นศ. ลงมือเขียน Test Cases ขั้นต่ำ 5 กรณี (เช่น ทดสอบ Login, ทดสอบฟอร์มเพิ่มอุปกรณ์)
3. ให้ นศ. สลับกันนำ Test Cases ของเพื่อนไปทำ Manual Test กับโปรเจกต์ของเพื่อน (Peer Testing)
		-  สุ่มถามผู้เรียนว่า Test Case ที่ดีควรมีลักษณะอย่างไร (ตอบ: ละเอียด ทำตามได้จริง ระบุผลลัพธ์ชัดเจน)

	ขั้นตรวจผลสำเร็จ  (Progress)
- ผู้เรียนและครูผู้สอนตรวจสอบเอกสาร Test Cases ที่เขียนขึ้นว่าครบถ้วนตามหลักการหรือไม่
- การสรุปสาระสำคัญลงในสมุดจด  ครูผู้สอนตรวจสอบจากการถาม-ตอบของผู้เรียน

6.  การบูรณาการ (Integration)
6.1  เนื้อหาที่บูรณาการ (Content)
		- การบูรณาการภาษาอังกฤษ (CLIL) ในการใช้คำศัพท์ Test Plan, Test Case, Expected Result, Actual Result, Bug, Pass/Fail
	6.2  ขั้นตอนการจัดทำ (Process)
		- นำกระบวนการทางวิศวกรรมซอฟต์แวร์ (Software Engineering) มาปรับใช้เพื่อให้นักศึกษาเข้าใจถึงวงจรการพัฒนาที่ไม่ได้จบแค่การเขียนโค้ด
7.  สื่อ – อุปกรณ์ (Materials) 
สื่อนำเสนอ PowerPoint เรื่อง การเขียนแผนการทดสอบ (Software Testing)
ใบความรู้ (Information Sheet) เรื่อง Test Plan และ Test Cases (`wk8-content1-testplan.md`)
ใบทดสอบ (Test Sheet) เรื่อง Test Plan
ใบสั่งงาน (Job Sheet) เรื่อง Test Plan
ใบประเมินผลการปฏิบัติงาน (Evaluation Sheet) เรื่อง Test Plan
8.  การวัด และประเมินผล (Measurement and Evaluation)
การสังเกตพฤติกรรมจากการแสดงความสนใจ การแสดงความคิดเห็น การถาม – ตอบในชั้นเรียน
ประเมินผลการทำแบบทดสอบ
การตรวจงานจากการทำใบสั่งงาน (Job Sheet) (การเขียนเอกสาร Test Cases)
การตรวจผลงานจากการปฏิบัติงานตามใบประเมินผลการปฏิบัติงาน (Evaluation Sheet) 
ผลการวัดได้ประเมินผลผ่านเกณฑ์ 80% ตามจุดประสงค์การเรียนรู้ทุกข้อ
9.  กิจกรรมเสนอแนะ (Optional Activities)

การเขียนแผนการทดสอบ (Test Plan)
- **ทำไมต้องมี Test Plan:** หากไม่มีการวางแผนการทดสอบ นักพัฒนามักจะทดสอบแค่ "กรณีที่ถูกต้อง (Happy Path)" ทำให้เวลาผู้ใช้นำไปใช้งานจริงแล้วทำสิ่งที่คาดไม่ถึง ระบบมักจะล่ม Test Plan จะบังคับให้เราคิดถึงกรณีที่เป็นไปได้ทั้งหมด ทั้งที่ถูกและที่ผิด
- **Test Case (กรณีทดสอบ):** คือเอกสาร/ตารางที่ระบุขั้นตอนการทำงานทีละขั้นตอนอย่างละเอียดเพื่อให้ใครก็ตามสามารถอ่านและทำตามได้ ประกอบด้วย: รหัสกรณีทดสอบ (TC-001), ชื่อการทดสอบ, ขั้นตอน (Steps), สิ่งที่คาดหวัง (Expected Result), ผลที่ได้จริง (Actual Result), และสถานะ (Pass/Fail)
- **การทดสอบแบบ Manual:** ในรายวิชานี้เราเน้นให้ผู้เรียนสวมหมวกเป็น "ผู้ใช้งานทั่วไป" (User/QA) ทำการกดปุ่มและกรอกข้อมูลจริงหน้าจอทีละเมนู เพื่อค้นหาข้อผิดพลาดที่เกิดขึ้นบนเบราว์เซอร์
