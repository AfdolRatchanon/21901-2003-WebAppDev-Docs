หัวเรื่อง (Sub Unit)/งาน (JOB) ปฏิบัติงาน Lab: Navbar และ Complete Auth Flow

1.  สาระสำคัญ (Concept) 
	การพัฒนาโครงสร้างของเว็บแอปพลิเคชันให้สมบูรณ์ จะต้องมีแถบนำทาง (Navbar) ที่เปลี่ยนแปลงไปตามสถานะของผู้ใช้ (ล็อกอินแล้ว หรือ ยังไม่ล็อกอิน) โดยการประยุกต์ใช้ React Router ในการจัดกลุ่มเส้นทาง (Route Layout) ให้ระบบมีสิทธิพิเศษสำหรับผู้ใช้ทั่วไปกับผู้ดูแลระบบ (Admin) สัปดาห์นี้จะเป็นการทดสอบสร้าง Auth Flow ที่สมบูรณ์ ผนวกกับการดักจับเส้นทาง Protected Route และเพิ่มปุ่ม Logout เพื่อลบเซสชันออกจากระบบ 

2.  สมรรถนะหลัก/ย่อย (Unit of Competence / Element of Competence)
1. มีทักษะในการออกแบบและพัฒนา Layout ของแอปพลิเคชัน (Navbar และหน้าเว็บหลัก)
2. มีทักษะในการประยุกต์ใช้ Protected Route ในการป้องกันผู้ไม่มีสิทธิ์ให้เปลี่ยนเส้นทาง (Redirect)
3. มีความสามารถในการจัดทำระบบ Logout และเคลียร์ข้อมูล Storage/Context ได้
4. มีเจตคติและกิจนิสัยที่ดีในการปฏิบัติงานด้วยความละเอียดรอบคอบ รับผิดชอบ

3.  จุดประสงค์เชิงพฤติกรรม (Behavioral Objective)
1. สร้าง Component Navbar เพื่อใช้เป็นส่วนบนของทุกๆ หน้าจอได้
2. ผูกเงื่อนไขแสดงผลเมนูบน Navbar ตามสถานะการ Login ของผู้ใช้งานได้ (Conditional Rendering)
3. สร้างฟังก์ชัน Logout เพื่อลบ Token และเปลี่ยนหน้าจอกลับไปยังหน้า Login ได้
4. ปฏิบัติงานตามนโยบาย Lab โดยการแสดงชื่อและรหัสนักเรียนใน `<footer>` บนหน้าเว็บได้
5. ส่งงานโดยการ Push โค้ดขึ้น GitHub Repository ส่วนตัวและเขียนสรุปได้อย่างถูกต้อง
6. ประเมินผลงานและหาข้อผิดพลาดที่พบระหว่างการทำงานได้
7. แสดงความสนใจต่องานที่ได้รับมอบหมายได้เป็นอย่างดีเมื่อครูมอบหมายงานให้ทำ
8. ประยุกต์แนวทางการพัฒนาแบบเศรษฐกิจพอเพียงในเรื่องการประหยัดอดออมในการใช้อุปกรณ์อย่างรู้คุณค่า
9. ประยุกต์ใช้เป็นแนวทางในการดำเนินชีวิตอย่างสุจริตได้
5.  กิจกรรมการเรียนรู้ (Teaching / Learning Activities)

	หัวข้อที่/งานที่ (Sub  Unit/Main Job)  :  ปฏิบัติงาน Lab: Navbar และ Complete Auth Flow
	ขั้นนำเข้าสู่บทเรียน  (Motivation)  
1. ครูแสดงหน้าเว็บไซต์ต่างๆ และให้สังเกตว่าแถบเมนูด้านบน (Navbar) มีการเปลี่ยนปุ่ม "เข้าสู่ระบบ" เป็นภาพโปรไฟล์หลังจากที่ผู้ใช้ล็อกอินสำเร็จ
2. ครูถามนักเรียนว่าจะใช้ความรู้ใดใน React เพื่อทำเงื่อนไขนี้ (ตอบ: Conditional Rendering และ Context)
3. ครูอธิบายการลงมือปฏิบัติเพื่อรวบรวมระบบที่เรียนมาทั้งหมดให้เป็นแอปพลิเคชันเดียวที่เชื่อมโยงกันได้
	ขั้นการให้เนื้อหาความรู้  (Information)  
1. ขอบข่ายเนื้อหาหลัก
Navbar UI: การจัดวาง Layout ให้อยู่เหนือ `<Outlet />` ของ React Router
Conditional Rendering in Auth: การดึง `user` ออกจาก AuthContext เพื่อตรวจสอบว่ามีค่าหรือไม่ แล้วเลือกว่าจะเรนเดอร์เมนูใด
Logout Function: การทำงานของระบบออกจากระบบเพื่อทำลายเซสชัน
2. แนวทางการจัดกิจกรรมการสอน

2.2 ถามและตอบคำถามนักเรียนพร้อมกับอธิบายขั้นตอนการทำ Lab 
2.3 สาธิตการรวมระบบ Router กับ Navbar เข้าด้วยกันเพื่อสร้าง Layout สมบูรณ์
2.4 อธิบายกระบวนการเคลียร์ข้อมูลใน Context และ LocalStorage เมื่อผู้ใช้กดออกจากระบบ
ขั้นการประยุกต์เนื้อหา  (Application) 
1. ให้ นศ. ศึกษาใบงานและปฏิบัติตามขั้นที่ 0: นำชื่อ-รหัสนักเรียนไปใส่ใน `<footer>`
2. ให้ นศ. ปฏิบัติงานสร้าง Navbar และเขียนคำสั่งซ่อนปุ่มบางปุ่มหากยังไม่ได้ล็อกอิน
3. ให้ นศ. เขียนฟังก์ชัน Logout และทดสอบระบบป้องกัน Protected Route
		-  สุ่มถามผู้เรียนว่าเมื่อกดปุ่ม Logout ไปแล้ว พยายามกดปุ่ม "ย้อนกลับ (Back)" ของเบราว์เซอร์จะสามารถเข้าดูข้อมูลลับได้อีกหรือไม่

- **การจัดการ Layout และ Navbar** แอปพลิเคชันที่ดีมักจะมีส่วนหัวหรือส่วนท้ายที่ใช้ร่วมกันในหลายๆ หน้า React Router เปิดให้เราสร้าง `<Layout />` หุ้ม `<Outlet />` ซึ่งจุดไหนที่เป็น Outlet จะถูกสลับเป็นหน้าจอ Component ลูกตาม URL ที่เปิด
- **Complete Auth Flow** วงจรการยืนยันตัวตนที่สมบูรณ์มี 3 ส่วนคือ:
  1. Login: ส่งรหัส รับ Token มาเก็บใน LocalStorage และอัปเดตสถานะ (State) ว่าเข้าระบบแล้ว
  2. Protected Request & Routes: แอบดึง Token ไปแนบหัว HTTP Request (Axios Interceptor) และมีการดักไม่ให้ผู้ใช้ภายนอกเข้าหน้าสำคัญ
  3. Logout: เมื่อกดปุ่ม ลบ Token ทิ้ง เคลียร์ State และดีดกลับสู่หน้าแรก ถือเป็นการจบวงจร
- **Conditional Rendering (การเรนเดอร์ตามเงื่อนไข)** Navbar มักจะตรวจสอบสถานะจาก AuthContext เช่น ถ้า `isAuthenticated == true` จะแสดงชื่อและปุ่ม Logout ถ้าเป็น `false` จะแสดงปุ่ม Sign In หรือ Register แทน
