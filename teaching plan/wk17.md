หัวเรื่อง (Sub Unit)/งาน (JOB) การนำเสนอโปรเจกต์และการสอบป้องกัน (Project Defense)

1.  สาระสำคัญ (Concept) 
	การนำเสนอโปรเจกต์ (Project Defense) เป็นการประเมินผลสมรรถนะการปฏิบัติงานจริง โดยนักศึกษาจะต้องนำเสนอโปรเจกต์ "ระบบเบิก-จ่ายอุปกรณ์ไอที" ต่อหน้าคณะกรรมการ (ครูผู้สอนและ/หรือผู้ทรงคุณวุฒิ) เพื่อพิสูจน์ความเข้าใจในโค้ดที่เขียน (Code Reading & Understanding) อธิบายการออกแบบระบบ (Design Decision) และสาธิตการทำงานจริง (Live Demo) พร้อมทั้งตอบคำถามเชิงเทคนิค (Technical Interview) เกี่ยวกับเทคโนโลยีที่ใช้ ได้แก่ React, TypeScript, Node.js และ Socket.io

2.  สมรรถนะหลัก/ย่อย (Unit of Competence / Element of Competence)
1. มีความสามารถในการนำเสนอผลงานและสาธิตการทำงานของแอปพลิเคชันอย่างเป็นขั้นตอน
2. มีทักษะในการอธิบายโครงสร้างเทคโนโลยี (Technical Stack) และเหตุผลในการเลือกใช้เทคโนโลยี
3. มีความเข้าใจอย่างลึกซึ้งใน Source Code ที่พัฒนาขึ้น และสามารถตอบคำถามเชิงเทคนิคได้
4. มีความสามารถในการวิเคราะห์ปัญหาที่พบระหว่างการพัฒนาและเสนอแนวทางแก้ไขได้อย่างสมเหตุสมผล

3.  จุดประสงค์เชิงพฤติกรรม (Behavioral Objective)
1. นำเสนอโปรเจกต์และสาธิตฟังก์ชันการทำงานครบถ้วนภายในเวลาที่กำหนด (15 นาที) ได้
2. อธิบายการทำงานของระบบรักษาความปลอดภัย (JWT) และระบบ Real-time (Socket.io) ได้อย่างถูกต้อง
3. ตอบคำถามเกี่ยวกับข้อดีและประโยชน์ของการใช้งาน TypeScript ในโปรเจกต์ได้
4. อธิบายเหตุผลที่เลือกใช้ React และข้อดีของการใช้ Custom Hooks หรือ Context API ได้
5. ปฏิบัติงานเตรียมความพร้อมของ Environment สำหรับการ Demo ได้สมบูรณ์
6. แสดงความสนใจต่องานที่ได้รับมอบหมายได้เป็นอย่างดีเมื่อครูมอบหมายงานให้ทำ
7. ประยุกต์แนวทางการพัฒนาแบบเศรษฐกิจพอเพียงในเรื่องการประหยัดอดออมในการใช้อุปกรณ์อย่างรู้คุณค่า
8. ประยุกต์ใช้เป็นแนวทางในการดำเนินชีวิตอย่างสุจริตได้
5.  กิจกรรมการเรียนรู้ (Teaching / Learning Activities)
	-  ทบทวนผลการนำระบบขึ้นใช้งานจริง (Go Live) จากสัปดาห์ที่ 16
	เรื่องที่/งานที่ (Sub Topic/Job)  :   การนำเสนอโปรเจกต์และการทดสอบโค้ด
	หัวข้อที่/งานที่ (Sub  Unit/Main Job)  :  Project Defense + Code Interview
	ขั้นนำเข้าสู่บทเรียน  (Motivation)  
1. ครูอธิบายว่า โปรเจกต์ที่เสร็จสมบูรณ์แล้วจะไม่มีความหมายหากเราไม่สามารถอธิบายให้ผู้อื่นเข้าใจได้ว่า "ทำอะไร ทำไม และทำอย่างไร"
2. ครูยกตัวอย่างสถานการณ์การสัมภาษณ์งาน (Technical Interview) ในบริษัทซอฟต์แวร์ เพื่อกระตุ้นให้นักศึกษาเห็นความสำคัญของการสอบป้องกันโปรเจกต์ (Project Defense)
	ขั้นการให้เนื้อหาความรู้  (Information)  
1. ขอบข่ายเนื้อหาหลัก
โครงสร้างการนำเสนอ (15 นาที): เปิดตัวโปรเจกต์, Demo ระบบ, Technical Stack, ความท้าทาย/ปัญหาที่พบ, และ Q&A
Demo Checklist: ขั้นตอนการสาธิตระบบตั้งแต่ Login, Role Management, Real-time Updates (2 Tabs), และระบบป้องกันสิทธิ์ (Protected Routes)
Technical Questions: การเตรียมตอบคำถามยอดฮิต เช่น ทำไมใช้ React? JWT ปลอดภัยไหม? ระบบ Real-time ทำงานอย่างไร? และ TypeScript ช่วยอะไร?
2. แนวทางการจัดกิจกรรมการสอน
2.1 แจกเอกสารใบความรู้เรื่อง `wk9-project-defense.md` ให้นักศึกษาทำความเข้าใจเกณฑ์การประเมิน
2.2 ครูสาธิต (Role-play) การนำเสนอที่ดีและการนำเสนอที่ต้องปรับปรุงให้ดูเป็นตัวอย่าง
2.3 อธิบายข้อควรระวังในการ Demo เช่น การจัดการ Error, การใช้ Hardcoded Credentials, และการตั้งค่าหน้าจอให้พร้อม
ขั้นการประยุกต์เนื้อหา  (Application) 
1. ให้นักศึกษาใช้เวลาช่วงแรกในการเตรียม Demo Environment (รัน Backend, ตั้งค่า Database, เปิด Browser Tabs)
2. ให้นักศึกษาทำการซ้อมนำเสนอด้วยตนเองและแบบ Peer Review สลับกันตั้งคำถามกับเพื่อน
3. เริ่มดำเนินการสอบ Project Defense ทีละกลุ่ม/บุคคล ต่อหน้าคณะกรรมการ ตาม Checklist
		-  ตั้งคำถามให้นักศึกษาทดลองอธิบาย Source Code บางส่วน เช่น การทำงานของ `useEffect` ในการต่อ Socket.io

	ขั้นตรวจผลสำเร็จ  (Progress)
- ครู/คณะกรรมการ ประเมินผลการนำเสนอตาม Rubric (Demo ครบถ้วน, อธิบาย Technical Stack, ตอบคำถาม, และ Code Quality)
- แจ้งผลการประเมินเบื้องต้นและให้ Feedback เพื่อการพัฒนาแก่นักศึกษาเป็นรายบุคคล

6.  การบูรณาการ (Integration)
6.1  เนื้อหาที่บูรณาการ (Content)
		- การบูรณาการภาษาอังกฤษแบบ CLIL ให้ผู้เรียนเข้าใจคำศัพท์ Project Defense, Demo, Technical Stack, Design Decision, Stakeholder
	6.2  ขั้นตอนการจัดทำ (Process)
		- การนำทักษะการสื่อสาร (Communication Skills) และการคิดเชิงวิพากษ์ (Critical Thinking) มาประยุกต์ใช้ในการอธิบายกระบวนการคิดและแก้ปัญหา

การนำเสนอโปรเจกต์และการสอบป้องกัน (Project Defense)
- **Project Defense** คือการพิสูจน์ว่าผลงานที่เราสร้างขึ้นมานั้น "เป็นฝีมือเราจริง" และ "เราเข้าใจโครงสร้างทุกฟันเฟืองที่ขับเคลื่อนอยู่" เป็นการยืนยันความรู้ความสามารถต่อหน้าคณะกรรมการ
- **Technical Stack vs Features**
  - **Feature** คือสิ่งที่ระบบทำได้ เช่น การยืม/คืน อุปกรณ์
  - **Technical Stack** คือเทคโนโลยีที่ใช้สร้าง Feature นั้นและ "ทำไม" ถึงเลือกใช้ เช่น เลือกใช้ Socket.io เพื่อให้ระบบอัปเดตสถานะได้แบบ Real-time โดยที่เบราว์เซอร์ไม่ต้องรีเฟรชหน้า
- **คำถามที่พบบ่อย (FAQ)**
  - ทำไมเลือก React? (ตอบ: Community ใหญ่, Ecosystem ครบถ้วน, ตลาดแรงงานต้องการสูง)
  - TypeScript ช่วยอะไร? (ตอบ: ป้องกัน Bug จาก Type Mismatch, ช่วยเรื่อง Auto-complete, ทำให้โค้ดอ่านง่ายและปลอดภัยขึ้น)
  - JWT ปลอดภัยไหม? (ตอบ: ในรูปแบบ localStorage ยอมรับได้ในระดับการศึกษา แต่ใน Production จริงควรใช้ HttpOnly Cookie เพื่อป้องกัน XSS)
