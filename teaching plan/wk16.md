รหัสวิชา (Code)     21901-2003  	วิชา (Subject)     การพัฒนาเว็บแอปพลิเคชัน                                                        
หน่วยที่ (Unit)       8		ชื่อหน่วย (Name of Unit)     Test & Deploy (การทดสอบและการนำระบบขึ้นใช้งานจริง)
หัวเรื่อง (Sub Unit)/งาน (JOB) การนำระบบขึ้นใช้งานจริง (Deployment) และปฏิบัติงาน Lab

1.  สาระสำคัญ (Concept) 
	ขั้นตอนสุดท้ายในการพัฒนาเว็บแอปพลิเคชันคือการนำโปรเจกต์ที่พัฒนาเสร็จสิ้นและผ่านการทดสอบแล้ว ขึ้นไปวางบนเซิร์ฟเวอร์ (Deployment / Go Live) เพื่อให้ผู้ใช้ทั่วไปสามารถเข้าถึงได้ผ่านอินเทอร์เน็ต กระบวนการนี้รวมถึงการสร้าง Build (Production Bundle), การตั้งค่าตัวแปรสภาพแวดล้อม (Environment Variables) เพื่อแยกข้อมูลระหว่างโหมดพัฒนากับโหมดใช้งานจริง และการปฏิบัติงาน Lab แบบจำลองสถานการณ์การส่งมอบระบบ (Demo) แก่ผู้ใช้งาน

2.  สมรรถนะหลัก/ย่อย (Unit of Competence / Element of Competence)
1. มีความเข้าใจกระบวนการ Build และ Deploy เว็บแอปพลิเคชันที่สร้างด้วย Vite
2. มีทักษะในการใช้งาน Environment Variables (`.env`) เพื่อจัดการข้อมูลความลับหรือ URL API
3. มีความสามารถในการนำโปรเจกต์ขึ้นโฮสต์ (Hosting Provider เช่น Vercel, Netlify, Render)
4. มีทักษะในการนำเสนอสาธิตระบบ (System Demo) อย่างเป็นมืออาชีพ

3.  จุดประสงค์เชิงพฤติกรรม (Behavioral Objective)
1. อธิบายความแตกต่างระหว่าง Development Mode และ Production Mode ได้
2. จัดการไฟล์ `.env` และเรียกใช้งานตัวแปร `import.meta.env` ใน React ได้อย่างถูกต้อง
3. ดำเนินการ Build ระบบ (สร้างโฟลเดอร์ `dist`) เพื่อเตรียมพร้อมสำหรับนำขึ้นเซิร์ฟเวอร์ได้
4. ปฏิบัติงานนำระบบขึ้นสู่ Hosting จำลองและสาธิตการทำงาน (Go Live Simulation) ได้
5. ปฏิบัติงานตามนโยบาย Lab โดยการแสดงชื่อและรหัสนักเรียนใน `<footer>` บนหน้าเว็บได้
6. ส่งงานโดยการ Push โค้ดขึ้น GitHub Repository ส่วนตัวและส่งลิงก์ใช้งานจริง (Live URL) ได้
7. แสดงความสนใจต่องานที่ได้รับมอบหมายได้เป็นอย่างดีเมื่อครูมอบหมายงานให้ทำ
8. ประยุกต์แนวทางการพัฒนาแบบเศรษฐกิจพอเพียงในเรื่องการประหยัดอดออมในการใช้อุปกรณ์อย่างรู้คุณค่า
9. ประยุกต์ใช้เป็นแนวทางในการดำเนินชีวิตอย่างสุจริตได้
5.  กิจกรรมการเรียนรู้ (Teaching / Learning Activities)
	-  ทบทวนผลการเขียน Test Cases และการแก้ไข Bug จากสัปดาห์ที่ 15
	เรื่องที่/งานที่ (Sub Topic/Job)  :   การนำระบบขึ้นใช้งานจริง (Go Live)
	หัวข้อที่/งานที่ (Sub  Unit/Main Job)  :  Deploy + Environment Variables, Lab: Go Live Simulation + Demo
	ขั้นนำเข้าสู่บทเรียน  (Motivation)  
1. ครูตั้งคำถามว่า ตอนนี้โปรเจกต์เราทำงานได้ดีบน `localhost` แต่ถ้าอยากให้เพื่อนหรือลูกค้าเปิดดูจากมือถือของเขาเอง เราจะต้องทำอย่างไร
2. ครูสาธิตความแตกต่างของขนาดไฟล์ซอร์สโค้ด (ที่ใหญ่และทำงานช้า) เทียบกับไฟล์ที่ผ่านการ Build (ที่มีขนาดเล็กและโหลดเร็วมาก)
3. ครูอธิบายว่าการนำแอปพลิเคชันขึ้นเซิร์ฟเวอร์คือการ Go Live ซึ่งเป็นปลายทางสุดท้ายของโปรเจกต์
	ขั้นการให้เนื้อหาความรู้  (Information)  
1. ขอบข่ายเนื้อหาหลัก
Environment Variables: การซ่อนข้อมูล API Key หรือ URL ลงในไฟล์ `.env` เพื่อป้องกันความปลอดภัย ไม่ฝังโค้ดแข็ง (Hardcode)
Build Process: การทำงานของคำสั่ง `npm run build` ใน Vite เพื่อแพ็กไฟล์ทั้งหมดรวมเป็น HTML, CSS, JS ขนาดเล็ก (โฟลเดอร์ `dist`)
Deployment & Demo: ขั้นตอนการนำโฟลเดอร์ `dist` ขึ้นผู้ให้บริการโฮสติ้งฟรี และการจำลองนำเสนอ
2. แนวทางการจัดกิจกรรมการสอน
2.1 จัดเตรียมใบความรู้เรื่อง Deploy และใบงานปฏิบัติ Lab (`wk8-content2-deploy.md`, `wk8-lab1-golive.md`) ให้กับนักศึกษา
2.2 อธิบายเรื่องไฟล์ `.env` พร้อมสาธิตการแก้ไข API URL จากที่เคยเขียนตรงๆ ให้ดึงจาก `import.meta.env`
2.3 สาธิตกระบวนการ Build โปรเจกต์ และอัปโหลดไปยังโฮสติ้งฟรี (เช่น Vercel หรือ Firebase Hosting)
2.4 อธิบายกระบวนการใน Lab: Go Live Simulation
ขั้นการประยุกต์เนื้อหา  (Application) 
1. ให้ นศ. ศึกษาใบงานและดำเนินการแยก URL เป็น Environment Variable
2. ให้ นศ. ปฏิบัติการ Build ระบบและ Deploy ขึ้น Hosting ของตนเอง
3. ให้ นศ. ทดสอบเปิดเว็บไซต์จากลิงก์จริง (URL) บนอุปกรณ์อื่น (เช่น สมาร์ตโฟน) และทำการสาธิต
		-  สุ่มถามผู้เรียนว่าทำไมเราจึงไม่ควรนำไฟล์ `.env` ขึ้นไปไว้บน GitHub Repository ด้วย (ติด `.gitignore` ไว้)

	ขั้นตรวจผลสำเร็จ  (Progress)
- ผู้เรียนตรวจสอบความถูกต้องของเว็บไซต์จาก URL จริง หากมีปัญหาเรื่อง Routing ให้อาจารย์แนะนำการตั้งค่า `_redirects` หรือ Rewrite Rule
- การตรวจเช็ครายบุคคล ครูผู้สอนเดินตรวจ หรือตรวจสอบคืบหน้าจากการที่นักเรียนส่ง Live URL พร้อมข้อสรุปใน Google Docs

การนำระบบขึ้นใช้งานจริง (Deployment) และปฏิบัติงาน Lab
- **Environment Variables (.env)** คือไฟล์สำหรับเก็บตัวแปรที่เปลี่ยนแปลงไปตามสภาพแวดล้อม (เช่น API URL ของเครื่องนักพัฒนา กับ API URL ของเซิร์ฟเวอร์จริงจะไม่เหมือนกัน) การใช้ `.env` ทำให้เราแก้ไขแค่ไฟล์เดียวโดยไม่ต้องแก้โค้ดหลายจุด และข้อมูลจะไม่ถูกฝังตายตัวในโค้ด (ใน Vite จะเรียกใช้ผ่าน `import.meta.env.VITE_...`)
- **Build Process** การรันโค้ดบนเครื่องนักพัฒนา (`npm run dev`) ใช้เอนจินพิเศษที่ไม่ได้ถูกปรับแต่งเพื่อความเร็ว แต่การรัน `npm run build` จะประมวลผลโค้ดทั้งหมด บีบอัดภาพ ลบช่องว่าง ตัดโค้ดที่ไม่ได้ใช้ออก จนเหลือเพียงโฟลเดอร์ `dist/` (Distribution) ซึ่งเบาที่สุดและพร้อมนำไปใช้บนเซิร์ฟเวอร์
- **Deployment (Go Live)** คือการนำโฟลเดอร์ `dist/` ไปอัปโหลดบนโฮสติ้ง ซึ่งในยุคใหม่มีผู้ให้บริการอย่าง Vercel หรือ Netlify ที่สามารถเชื่อมต่อกับ GitHub Repository ของเราและทำการ Build ให้เราโดยอัตโนมัติ (CI/CD เบื้องต้น) ทุกครั้งที่เรา Push โค้ด
