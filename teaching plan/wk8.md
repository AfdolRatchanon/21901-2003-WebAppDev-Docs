หัวเรื่อง (Sub Unit)/งาน (JOB) การจัดการ Database Schema Types และปฏิบัติงาน Lab: เชื่อมต่อ API

1.  สาระสำคัญ (Concept) 
	การรับข้อมูล JSON จาก API จะไม่มีการรับประกันโครงสร้าง การใช้ TypeScript เพื่อกำหนด Interface เป็นดั่ง "ข้อตกลง (Contract)" ฝั่ง Frontend เพื่อป้องกันปัญหาในอนาคต ทำให้พัฒนาแอปพลิเคชันได้ง่ายขึ้นด้วย Utility Types อย่าง `Pick<T, K>` นอกจากนี้ในการสร้างหน้าจอจำเป็นต้องมีตัวแปรสถานะที่แจ้งผู้ใช้งาน (Loading State) หรือหากเกิดปัญหา (Error State) ใน Lab นี้จะเป็นการนำความรู้ทั้งหมดมาดึงข้อมูลอุปกรณ์ของระบบเบิก-จ่ายจาก API จริง นำมาเก็บเข้า State และแสดงผลบนหน้าจอ

2.  สมรรถนะหลัก/ย่อย (Unit of Competence / Element of Competence)
1. มีความเข้าใจหลักการกำหนด Database Schema Types และการใช้งาน Utility Types (`Pick`, `Partial`)
2. มีความเข้าใจในการจัดการตัวแปรสถานะ (State) สำหรับ Loading และ Error
3. มีทักษะในการประยุกต์ใช้ Fetch, Async/Await เข้ากับ Component (useEffect) เพื่อดึงข้อมูลจริง
4. มีเจตคติและกิจนิสัยที่ดีในการปฏิบัติงานด้วยความละเอียดรอบคอบ รับผิดชอบ

3.  จุดประสงค์เชิงพฤติกรรม (Behavioral Objective)
1. กำหนด Interface พื้นฐานของข้อมูล (`Equipment`, `User`) และประยุกต์ใช้ `Pick<T, K>` ได้อย่างถูกต้อง
2. จัดการตัวแปร Loading State และ Error State ในขณะที่กำลังเชื่อมต่อ API ได้
3. ปฏิบัติงาน Lab: ดึงข้อมูลอุปกรณ์จาก API จริง และแสดงผลออกมาเป็นการ์ดอุปกรณ์ด้วย `.map()` ได้
4. ปฏิบัติงานตามนโยบาย Lab โดยการแสดงชื่อและรหัสนักเรียนใน `<footer>` บนหน้าเว็บได้
5. ส่งงานโดยการ Push โค้ดขึ้น GitHub Repository ส่วนตัวและเขียนสรุปได้อย่างถูกต้อง
6. ประเมินผลงานและหาข้อผิดพลาดที่พบระหว่างการทำงานได้
7. แสดงความสนใจต่องานที่ได้รับมอบหมายได้เป็นอย่างดีเมื่อครูมอบหมายงานให้ทำ
8. ประยุกต์แนวทางการพัฒนาแบบเศรษฐกิจพอเพียงในเรื่องการประหยัดอดออมในการใช้อุปกรณ์อย่างรู้คุณค่า
9. ประยุกต์ใช้เป็นแนวทางในการดำเนินชีวิตอย่างสุจริตได้

	เรื่องที่/งานที่ (Sub Topic/Job)  :   การสร้าง Interface และ Lab ดึงข้อมูล
	หัวข้อที่/งานที่ (Sub  Unit/Main Job)  :  การจัดการ Database Schema Types และปฏิบัติงาน Lab: เชื่อมต่อ API
	ขั้นนำเข้าสู่บทเรียน  (Motivation)  
1. ครูแสดงปัญหาเรื่องโครงสร้างข้อมูลที่ส่งมาจาก Backend มักเป็น `any` และถามนักเรียนว่าจะเกิดผลกระทบอะไรถ้าระบบไม่รู้โครงสร้างของข้อมูล
2. ครูให้เห็นภาพตัวอย่างของ Utility Types เช่น นำข้อมูลผู้ใช้เฉพาะบางฟิลด์มาใช้
3. ครูสรุปเข้าเรื่องความสำคัญของการนิยาม Type และการเชื่อมต่อเพื่อนำข้อมูลเหล่านั้นมาใส่ในหน้าจอ (Lab)

แผ่นที่ :
การจัดการ Database Schema Types และปฏิบัติงาน Lab: เชื่อมต่อ API
- **Database Schema Types** ในการติดต่อกับ API มักจะได้ข้อมูลดิบในรูปแบบ JSON มาตรฐาน การสร้าง TypeScript Interface (เช่น `Equipment`) ช่วยป้องกันไม่ให้พิมพ์ผิด และมี Utility Types ที่มีประโยชน์เช่น `Pick<T, K>` เพื่อเลือกเฉพาะบางฟิลด์จาก Interface เต็ม ไปประยุกต์ใช้ได้
- **ApiResponse Wrapper** โดยทั่วไป API มักจะมีรูปแบบมาตรฐานในการตอบกลับ เช่น หุ้มข้อมูลไว้ด้วย `{ success: boolean, data: T }` การใช้ Generic `<T>` ทำให้เราสามารถใส่โครงสร้างตัวแปรใดๆ ลงไปก็ได้
- **Loading & Error States** การดึงข้อมูลจาก API ต้องใช้เวลา ระหว่างนั้นควรมีการแสดงคำว่า "กำลังโหลด..." แก่ผู้ใช้โดยใช้ State ตัวแปรเช็คสถานะ หากเกิดข้อผิดพลาดขึ้น ควรนำข้อความไปเก็บในตัวแปร Error และแสดงผลแจ้งเตือน ไม่ให้หน้าจอว่างเปล่า
- **ดึงข้อมูลใส่ Component** การจะดึง API เพื่อเอามาแสดงผลใน React จะนำเอาโค้ด `fetch` ไปใส่ใน `useEffect` จากนั้นรอผลลัพธ์และนำผลลัพธ์มาบันทึกอัปเดตลงตัวแปร Array ใน `useState` เพื่อเรนเดอร์หน้าจอใหม่ด้วยข้อมูลจริง
