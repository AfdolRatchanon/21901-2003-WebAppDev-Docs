แผนการสอนแบบฐานสมรรถนะ (Competency-based Teaching Plan)
สัปดาห์ที่ (Week)     6

รหัสวิชา (Code)     21901-2003  	วิชา (Subject)     การพัฒนาเว็บแอปพลิเคชัน                                                        
หน่วยที่ (Unit)       3		ชื่อหน่วย (Name of Unit)     UI + Forms (Validation และ ปฏิบัติงาน Lab)
หัวเรื่อง (Sub Unit)/งาน (JOB) การตรวจสอบข้อมูล (Validation) และ ปฏิบัติงาน Lab: ฟอร์มเบิกอุปกรณ์

1.  สาระสำคัญ (Concept) 
	หลังจากที่สร้างฟอร์มเพื่อรับข้อมูลได้แล้ว ขั้นตอนที่ขาดไม่ได้คือการตรวจสอบความถูกต้องของข้อมูล (Form Validation) เพื่อป้องกันไม่ให้ข้อมูลที่ผิดพลาดหรือไม่สมบูรณ์ถูกส่งเข้าระบบ ซึ่งสามารถทำได้ทั้งแบบ Manual หรือใช้ไลบรารีอย่าง Zod เข้ามาช่วย ในสัปดาห์นี้จะมุ่งเน้นการประยุกต์ใช้ความรู้จากสัปดาห์ก่อนมาปฏิบัติงาน Lab เพื่อสร้างหน้าจอ "ฟอร์มเบิกอุปกรณ์" (Asset Form) ที่มีการใช้งาน Tailwind CSS การผูก State และมีระบบแจ้งเตือน (Error Message) หากผู้ใช้กรอกข้อมูลไม่ครบถ้วน

2.  สมรรถนะหลัก/ย่อย (Unit of Competence / Element of Competence)
1. มีความเข้าใจหลักการตรวจสอบความถูกต้องของข้อมูล (Form Validation)
2. มีทักษะในการออกแบบและแสดงผลข้อความแจ้งเตือน Error บนหน้าเว็บ
3. มีความสามารถในการประยุกต์ใช้ความรู้สร้างฟอร์มสำหรับโปรเจกต์ได้
4. มีเจตคติและกิจนิสัยที่ดีในการปฏิบัติงานด้วยความละเอียดรอบคอบ รับผิดชอบ

3.  จุดประสงค์เชิงพฤติกรรม (Behavioral Objective)
1. อธิบายหลักการตรวจสอบข้อมูล (Validation) ก่อนการบันทึกได้
2. ปฏิบัติงาน Lab สร้างหน้าจอและฟอร์มเบิกอุปกรณ์ (Asset Form) ได้อย่างครบถ้วน
3. แสดงข้อความแจ้งเตือน Error เมื่อผู้ใช้งานกรอกข้อมูลไม่ตรงตามเงื่อนไขได้อย่างถูกต้อง
4. ปฏิบัติงานตามนโยบาย Lab โดยการแสดงชื่อและรหัสนักเรียนใน `<footer>` บนหน้าเว็บได้
5. ส่งงานโดยการ Push โค้ดขึ้น GitHub Repository ส่วนตัวและเขียนสรุปได้อย่างถูกต้อง
6. ประเมินผลงานและหาข้อผิดพลาดที่พบระหว่างการทำงานได้
7. แสดงความสนใจต่องานที่ได้รับมอบหมายได้เป็นอย่างดีเมื่อครูมอบหมายงานให้ทำ
8. ประยุกต์แนวทางการพัฒนาแบบเศรษฐกิจพอเพียงในเรื่องการประหยัดอดออมในการใช้อุปกรณ์อย่างรู้คุณค่า
9. ประยุกต์ใช้เป็นแนวทางในการดำเนินชีวิตอย่างสุจริตได้
5.  กิจกรรมการเรียนรู้ (Teaching / Learning Activities)
	-  ทบทวนเรื่อง Controlled Forms และการจัดการ Event จากสัปดาห์ที่ 5
	เรื่องที่/งานที่ (Sub Topic/Job)  :   ปฏิบัติงาน Lab จัดการฟอร์มและการตรวจสอบข้อมูล
	หัวข้อที่/งานที่ (Sub  Unit/Main Job)  :  การตรวจสอบข้อมูล (Validation) และ ปฏิบัติงาน Lab: ฟอร์มเบิกอุปกรณ์
	ขั้นนำเข้าสู่บทเรียน  (Motivation)  
1. ครูแสดงหน้าจอตัวอย่างเวลาผู้ใช้งานกรอกแบบฟอร์มแล้วลืมใส่ข้อมูลสำคัญ ระบบจะมีกรอบสีแดงพร้อมข้อความแจ้งเตือน
2. ครูถามนักเรียนว่าหากไม่มีการเตือนและปล่อยให้บันทึก จะเกิดผลเสียกับระบบฐานข้อมูลอย่างไร
3. ครูสรุปเข้าเรื่องความจำเป็นของการทำ Form Validation เพื่อกรองข้อมูลก่อนเข้าสู่ระบบ
	ขั้นการให้เนื้อหาความรู้  (Information)  
1. ขอบข่ายเนื้อหาหลัก
Form Validation: การเช็คเงื่อนไข (Condition) เช่น ช่องว่าง ความยาวตัวอักษร ด้วยการเขียนโปรแกรม (Manual) หรือใช้เครื่องมือ (Zod)
Error State: การสร้างตัวแปร State เพื่อเก็บข้อความแจ้งเตือนและนำมาแสดงผลเป็นข้อความสีแดงด้วย Tailwind CSS
Lab: การประกอบ UI ของฟอร์มเบิกอุปกรณ์ให้สมบูรณ์ รองรับการส่ง Event ยืนยันการบันทึก
2. แนวทางการจัดกิจกรรมการสอน
2.1 จัดเตรียมใบความรู้เรื่อง Validation และใบงานปฏิบัติ Lab (wk3-content3-validation.md, wk3-lab1-asset-form.md) ให้กับนักศึกษา
2.2 ถามและตอบคำถามนักเรียนพร้อมกับอธิบายขั้นตอนการทำ Lab การส่งงาน
2.3 สาธิตการเขียนเงื่อนไขตรวจสอบช่องว่างของ Input แบบ Manual เพื่อสร้างความเข้าใจ
2.4 อธิบายกระบวนการตรวจเช็ค Error Message ที่แสดงผลบนหน้าจอ
ขั้นการประยุกต์เนื้อหา  (Application) 
1. ให้ นศ. ศึกษาใบงานและปฏิบัติตามขั้นที่ 0: นำชื่อ-รหัสนักเรียนไปใส่ใน `<footer>`
2. ให้ นศ. ปฏิบัติงานสร้างฟอร์มเบิกอุปกรณ์ (Asset Form) โดยใช้ Tailwind CSS ในการตกแต่ง
3. ให้ นศ. พัฒนาระบบตรวจสอบ (Validation) เพื่อไม่ให้กดตกลงหากใส่ข้อมูลไม่ครบ
		-  สุ่มถามผู้เรียนถึงกลไกการแสดงข้อความแจ้งเตือน Error ว่าจะทำงานและหายไปเมื่อใด

	ขั้นตรวจผลสำเร็จ  (Progress)
- ผู้เรียนตรวจสอบความถูกต้องของฟอร์ม และลองกรอกข้อมูลแบบไม่ครบเพื่อให้ระบบแสดง Error Message
- การตรวจเช็ครายบุคคล ครูผู้สอนเดินตรวจ หรือตรวจสอบคืบหน้าจากการที่นักเรียน Push โค้ดขึ้น GitHub และส่งลิงก์พร้อมข้อสรุปใน Google Docs

6.  การบูรณาการ (Integration)
6.1  เนื้อหาที่บูรณาการ (Content)
		- การบูรณาการภาษาอังกฤษแบบ CLIL ให้ผู้เรียนสร้างชื่อตัวแปร ข้อความ Error Message แจ้งเตือนผู้ใช้งานเป็นภาษาอังกฤษ
	6.2  ขั้นตอนการจัดทำ (Process)
		- การบูรณาการการใช้เครื่องมือควบคุมเวอร์ชัน (Git/GitHub) ในการบันทึกและตรวจสอบประวัติการแก้ไขโค้ด
7.  สื่อ – อุปกรณ์ (Materials) 
ใบความรู้และใบขั้นตอนการปฏิบัติงาน (Job Sheet) เรื่อง Form Validation และ Lab: ฟอร์มเบิกอุปกรณ์ + Error (`wk3-content3-validation.md`, `wk3-lab1-asset-form.md`)
ระบบ Google Docs สำหรับการบันทึกสรุปและส่งลิงก์ผลงาน
เครื่องคอมพิวเตอร์ ระบบปฏิบัติการ และโปรแกรมเบราว์เซอร์
ระบบ GitHub สำหรับการจัดการรหัสต้นฉบับ
8.  การวัด และประเมินผล (Measurement and Evaluation)
การสังเกตพฤติกรรมจากการแสดงความสนใจ การปฏิบัติงานในชั้นเรียน และการแก้ปัญหา
การตรวจงานจากการทำใบสั่งงาน (Job Sheet) เรื่อง Lab: ฟอร์มเบิกอุปกรณ์
การตรวจสอบความถูกต้องของการแสดงผล UI และระบบแจ้งเตือน Error
ตรวจผลการนำ Source Code ขึ้นจัดเก็บใน GitHub Repository และการบันทึกสรุปงาน
ผลการวัดได้ประเมินผลผ่านเกณฑ์ 80% ตามจุดประสงค์การเรียนรู้ทุกข้อ
9.  กิจกรรมเสนอแนะ (Optional Activities)

- **Form Validation** คือ กระบวนการตรวจสอบข้อมูลที่ผู้ใช้กรอกในแบบฟอร์ม เพื่อรับประกันว่าข้อมูลถูกต้องตามรูปแบบที่ระบบต้องการ เช่น ห้ามเป็นช่องว่าง ต้องเป็นตัวเลขเท่านั้น หรือต้องมีรูปแบบอีเมลที่ถูกต้อง โดยปกติจะทำก่อนการส่ง (Submit) ไปยังเซิร์ฟเวอร์
- **การจัดการ Error Message** โดยใช้ State เช่น `const [error, setError] = useState('')` หากระบบตรวจพบความผิดปกติของการกรอกข้อมูล จะนำข้อความแจ้งเตือนไปเก็บใน State และแสดงผลบนหน้าจอทันที ควบคู่กับการประยุกต์ใช้คลาสใน Tailwind CSS เช่น `text-red-500`
- **การใช้งานไลบรารีเสริม** ในโปรเจกต์ที่ซับซ้อน นักพัฒนามักใช้เครื่องมืออย่าง **Zod** หรือ **Yup** ร่วมกับ React Hook Form ในการตรวจสอบข้อมูลและออกรายงาน Error Message อย่างรวดเร็ว เพื่อลดภาระการเขียนโค้ดเช็คแบบ Manual ทีละเงื่อนไข
