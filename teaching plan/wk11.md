หัวเรื่อง (Sub Unit)/งาน (JOB) Cookies, localStorage และ Auth Session

1.  สาระสำคัญ (Concept) 
	ในการพัฒนาระบบที่มีการยืนยันตัวตน (Authentication) ระบบจำเป็นต้องจดจำผู้ใช้งานหลังจากที่เข้าสู่ระบบสำเร็จ โดยเทคนิคที่นิยมใช้คือการเก็บข้อมูลสถานะหรือ Token ไว้ใน Browser ผ่าน `localStorage` หรือ `Cookies` เพื่อไม่ให้ผู้ใช้งานต้องล็อกอินใหม่ทุกครั้งที่รีเฟรชหน้าเว็บ นอกจากนี้ การทำงานร่วมกับ API ที่ต้องระบุตัวตน จะใช้เครื่องมืออย่าง `Axios Interceptor` เพื่อแนบ Token ไปกับทุกคำขอ (Request) โดยอัตโนมัติ ซึ่งจะช่วยลดความซ้ำซ้อนในการเขียนโค้ดและทำให้ระบบมีความปลอดภัยมากยิ่งขึ้น

2.  สมรรถนะหลัก/ย่อย (Unit of Competence / Element of Competence)
1. มีความเข้าใจหลักการทำงานของ localStorage และ Cookies ใน Browser
2. มีทักษะในการเขียนคำสั่งเพื่อบันทึก อ่าน และลบข้อมูลใน Browser Storage
3. มีความเข้าใจหลักการทำงานของ Authentication Session และ Token
4. มีทักษะในการประยุกต์ใช้ Axios Interceptor สำหรับจัดการ API Requests

3.  จุดประสงค์เชิงพฤติกรรม (Behavioral Objective)
1. อธิบายความแตกต่างระหว่างการเก็บข้อมูลใน localStorage และ Cookies ได้
2. ใช้งานคำสั่ง JavaScript เพื่อจัดการข้อมูลใน Browser Storage ได้อย่างถูกต้อง
3. อธิบายกระบวนการสร้างและทำงานของ Auth Session ควบคู่กับ Token ได้
4. สร้างและใช้งาน Axios Interceptor เพื่อแนบ Token ในทุกคำขอได้อย่างถูกต้อง
5. เตรียมเครื่องคอมพิวเตอร์และสภาพแวดล้อมเพื่อการเรียนได้
6. เปิดโปรแกรมหรือเอกสารเพื่อศึกษาเนื้อหาควบคู่ได้อย่างถูกต้อง
7. สรุปเนื้อหาได้
8. แสดงความสนใจต่องานที่ได้รับมอบหมายได้เป็นอย่างดีเมื่อครูมอบหมายงานให้ทำ
9. ประยุกต์แนวทางการพัฒนาแบบเศรษฐกิจพอเพียงในเรื่องการประหยัดอดออมในการใช้อุปกรณ์อย่างรู้คุณค่า
10. ประยุกต์ใช้เป็นแนวทางในการดำเนินชีวิตอย่างสุจริตได้

	-  ทบทวนเนื้อหาการใช้ API จากก่อนกลางภาค และอธิบายการทำงานของระบบ Login

1. ครูให้นักเรียนทดลองล็อกอินเข้าสู่ระบบโซเชียลมีเดีย แล้วกดรีเฟรชหน้าเว็บ พร้อมถามว่าทำไมระบบถึงยังจำได้ว่าเราคือใคร
2. ครูสาธิตการลบ Cache / Cookies แล้วรีเฟรชใหม่ให้เห็นว่าระบบหลุดจากการล็อกอินทันที
3. ครูสรุปเข้าสู่เรื่องการใช้ Browser Storage (localStorage/Cookies) ในการรักษาสถานะเซสชัน
	ขั้นการให้เนื้อหาความรู้  (Information)  
1. ขอบข่ายเนื้อหาหลัก
Browser Storage: การใช้คำสั่ง `localStorage.setItem()`, `getItem()`, และ `removeItem()`
Auth Session: กระบวนการรับ Token จาก Backend และเก็บเข้า Storage พร้อมนำมาเก็บใน State ของ React (`User | null`)
Axios Interceptor: การแทรกแซง HTTP Request ก่อนส่งออกไป เพื่อเติม Header `Authorization: Bearer <Token>`

Cookies, localStorage และ Auth Session
- **Browser Storage** คือพื้นที่ที่เว็บเบราว์เซอร์จัดสรรไว้ให้แต่ละเว็บไซต์เก็บข้อมูล ซึ่ง localStorage จะเก็บข้อมูลแบบถาวรจนกว่าจะถูกลบ (เหมาะสำหรับการเก็บ Token) ส่วน Cookies มักใช้กับการส่งข้อมูลไปพร้อมกับ Request แบบดั้งเดิม
- **Auth Session** คือช่วงเวลาที่ระบบยอมรับว่าผู้ใช้คนนี้ได้ยืนยันตัวตนแล้ว การทำงานเริ่มจากเมื่อส่ง Username/Password ถูกต้อง Backend จะสร้างรหัส Token คืนมาให้ Frontend นำ Token นี้ไปเก็บไว้ใน Storage และนำมาตรวจสอบทุกครั้งที่โหลดหน้าเว็บใหม่ว่าเซสชันยังไม่หมดอายุ
- **Axios Interceptor** เป็นเหมือน "ด่านตรวจ" ที่เราเขียนดักไว้ก่อนที่ Axios จะทำการยิง API ออกไป โดยเราจะสั่งให้มันดึง Token จาก localStorage มาแนบใส่ในส่วนของ HTTP Header (`Authorization: Bearer <token>`) เสมอ ทำให้เราไม่ต้องมาเขียนโค้ดแนบ Token ด้วยตัวเองในทุกๆ หน้าจอที่มีการดึงข้อมูลลับ
